SQL Material Planning Demonstration

A runnable SQLite example compares project requirements with inventory, calculates material shortfalls, and ranks priorities without mixing units.

Download SQL ↓View repository ↗

Business question

Which materials have a shortfall when requirements from several projects are compared with available stock? This demonstration uses entirely synthetic projects and quantities to make the SQL logic inspectable.

Method and decisions

  • Define project, material, requirement and inventory tables with keys and quantity checks.
  • Aggregate requirements before joining inventory to prevent stock double-counting.
  • Use a left join and COALESCE to handle materials without a stock record.
  • Calculate shortfalls by material and use DENSE_RANK to prioritize the percentage gap.
  • Use a windowed total to show each project’s share of a material’s demand.

Interactive result

The all-project table shows the checked SQLite output. Selecting one project compares its requirements with the full shared stock pool for illustration; it does not allocate or reserve stock.

Why this supports a business decision

Shortfall percentage helps identify materials to investigate first without adding unlike units such as kilograms and litres together. The example does not account for purchase lead times, costs, delivery timing, substitutions, waste or reservations; those are required before real procurement decisions.

SQL excerpt

WITH demand AS (
  SELECT material_id, SUM(required_qty) AS required_qty
  FROM requirements
  GROUP BY material_id
)
SELECT m.material_name, m.unit, d.required_qty,
       COALESCE(i.available_qty, 0) AS available_qty,
       MAX(d.required_qty - COALESCE(i.available_qty, 0), 0)
         AS shortage_qty
FROM demand d
JOIN materials m USING (material_id)
LEFT JOIN inventory i USING (material_id);
